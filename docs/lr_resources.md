Implementation closure and biological-source closure are distinct. `data/lr_resource_evidence.json` contains all129 entries, original record fields, matching rules, code hashes and specific missing source/value records. The companion Supplementary File S1 workbook exposes these fields for review. Supplementary File S1 is a separate submission attachment, not implied to be inside the code package.

Query rules use whitespace/case normalization and underscore component splitting, not orthology inference. ## Scientific interpretation

Interpretation scope: the library is a transparent heuristic prior, not a set of independently validated binary interactions or calibrated biological strengths. NTNG1–NTRK2 has unresolved intended identity; ERBB2 receptor-association products and receptor-component projections are descriptive compatibility features. See docs/lr_resources.md.

The packaged default lrot_core.fgw_lr_solver lacks diagnostic arguments present in retained accepted records. A separately hash-bound source snapshot and wrapper under `paper_protocol/` have recorded fixed-input F7 verification; this does not certify every experiment. Asset export and saved-result drawing remain available; do not present the default legacy solve commands as certified end-to-end reproduction of the revised numerical results. No solver was changed in this review.

The numeric coefficients are empirical design choices; experimental calibration of every value is not required to disclose a heuristic. Missing calibration prohibits calling them measured strengths/database confidence, while an unresolved pair identity still requires evidence or an explicit resource-change decision. Existing HER2 ablation removes nine related pairs, not just ERBB2–ERBB2 and ERBB2–ERBB3.

Local related records: LRRC4C_NTNG1 (KEGG:mmu04514) and BDNF_NTRK2/NTF3_NTRK2/NTF5_NTRK2 (PMID:27908981) have different partners from NTNG1–NTRK2. They must not be used as direct support or silently substituted.

## Source obtainability: local-code review

The CellChatDB builder reads the local RDA interaction table, normalizes symbols, expands receptor components and assigns .9/.6 coefficients. The builder itself does not record an upstream commit, database release, acquisition receipt or licence. Subsequent public comparison now supplies a matching fixed upstream commit and its declared licence; this does not recover the original acquisition receipt. The RDA writer version 4.1.2 identifies the serialization writer, not the database release. Existing RDA/PKL hashes establish local file identity; code inspection cannot fill the missing upstream/permission fields in `data/resource_provenance.json`. Original acquisition fields remain unresolved. Current verified source/declared-licence information is in `data/external_sources.json`; the historical evidence is preserved. The binaries remain excluded from distribution.

For F3, the external source gate checks six installed STAligner files and package versions in [environment.json](../provenance/f3_staligner/environment.json). The package version alone does not identify this exact source with its recorded neighbour fallback. Public comparison now establishes a fixed upstream commit plus explicit patch that reconstruct the six source files, with the full upstream MIT notice. The recipe is bundled for offline preparation. Original installation route and patch author/date remain unknown; saved-embedding scoring remains available without that training source. See the [F3 case guide](../provenance/f3_staligner/README.md). No experimental input was substituted, and no historical acquisition or patch-authorship record was invented.
